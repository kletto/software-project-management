# Use Cases

**Проект:** Markdown-редактор.

**Основной актор:** Пользователь.

**Внешняя система:** Локальная файловая система, используемая для чтения и записи документов.

### UC-01. Открытие локального Markdown-файла

**Цель:** Пользователь хочет открыть существующий Markdown-файл для просмотра и редактирования.

**Актор:** Пользователь.

**Предусловия:**
- Приложение запущено.
- Пользователь имеет доступ к локальной файловой системе.

**Триггер:** Пользователь выбирает функцию открытия файла.

**Основной сценарий:**
1. Пользователь нажимает кнопку «Открыть файл».
2. Приложение отображает диалог выбора файла.
3. Пользователь выбирает нужный Markdown-файл.
4. Приложение считывает содержимое файла.
5. Приложение отображает содержимое документа в редакторе.

**Альтернативные и негативные сценарии:**
- Пользователь отменяет выбор файла — открытие не выполняется.
- Файл не существует или недоступен — приложение сообщает об ошибке.
- Файл имеет неподдерживаемый формат или не может быть прочитан — приложение сообщает о невозможности открытия.
- Файл пустой — приложение открывает пустой документ.

**Результат:** Выбранный документ открыт и доступен для редактирования.

### UC-02. Изменение текстового содержимого документа

**Цель:** Пользователь хочет добавить, удалить или изменить текст документа.

**Актор:** Пользователь.

**Предусловия:**
- Приложение запущено.
- В редакторе открыт документ.

**Триггер:** Пользователь помещает курсор в текст документа и начинает редактирование.

**Основной сценарий:**
1. Пользователь выбирает место в документе для редактирования.
2. Пользователь вводит, удаляет или заменяет текст.
3. Приложение обновляет текстовое содержимое документа.
4. Приложение отображает внесённые изменения.

**Альтернативные и негативные сценарии:**
- Пользователь удаляет весь текст документа — документ становится пустым.
- Пользователь отменяет редактирование — изменение отменяется в соответствии с функцией отмены действий.
- Ввод текста невозможен из-за технической ошибки — приложение сообщает об ошибке.

**Результат:** Содержимое документа изменено в редакторе.

### UC-03. Сохранение изменений в файл

**Цель:** Пользователь хочет сохранить внесённые изменения в локальный Markdown-файл.

**Актор:** Пользователь.

**Предусловия:**
- В редакторе открыт документ.
- Документ содержит изменения, которые необходимо сохранить.

**Триггер:** Пользователь нажимает кнопку «Сохранить».

**Основной сценарий:**
1. Пользователь нажимает кнопку «Сохранить».
2. Приложение получает текущее содержимое документа.
3. Приложение записывает изменения в соответствующий локальный файл.
4. Приложение сообщает об успешном сохранении.

**Альтернативные и негативные сценарии:**
- Пользователь пытается сохранить документ без изменений — приложение сообщает, что сохранять нечего, либо выполняет сохранение без изменения содержимого.
- Файл недоступен для записи — приложение сообщает об ошибке.
- Происходит ошибка при записи файла — приложение сообщает, что сохранить документ не удалось.

**Результат:** Изменения сохранены в локальном файле.

### UC-04. Изменение типа текстового блока

**Цель:** Пользователь хочет изменить структуру выбранного текстового блока.

**Актор:** Пользователь.

**Предусловия:**
- В редакторе открыт документ.
- В документе имеется текстовый блок, который можно изменить.

**Триггер:** Пользователь выбирает функцию изменения типа текстового блока.

**Основной сценарий:**
1. Пользователь помещает курсор в нужный блок или выделяет его.
2. Пользователь открывает меню изменения типа блока.
3. Пользователь выбирает новый тип блока.
4. Приложение преобразует исходный блок в выбранный тип.
5. Приложение отображает обновлённый документ.

**Альтернативные и негативные сценарии:**
- Пользователь закрывает меню без выбора — изменения не выполняются.
- Выбранный тип блока недоступен для текущего содержимого — приложение сообщает об этом или не позволяет выполнить преобразование.

**Результат:** Тип выбранного текстового блока изменён.

### UC-05. Применение стилей к выделенному тексту

**Цель:** Пользователь хочет изменить оформление определённой части текста.

**Актор:** Пользователь.

**Предусловия:**
- В редакторе открыт документ.
- В документе имеется текст, доступный для выделения.

**Триггер:** Пользователь выделяет текст и выбирает функцию форматирования.

**Основной сценарий:**
1. Пользователь выделяет нужный фрагмент текста.
2. Пользователь открывает меню форматирования или использует панель инструментов.
3. Пользователь выбирает необходимый стиль.
4. Приложение добавляет соответствующее Markdown-форматирование к выделенному тексту.
5. Приложение отображает текст с применённым стилем.

**Альтернативные и негативные сценарии:**
- Пользователь не выделил текст — приложение не применяет форматирование и сообщает о необходимости выделения.
- Пользователь отменяет выбор стиля — форматирование не применяется.
- Пользователь выбирает уже применённый стиль — приложение обрабатывает действие согласно правилам редактора.

**Результат:** К выделенному фрагменту текста применён выбранный стиль.

### UC-06. Отмена последнего изменения

**Цель:** Пользователь хочет отменить последнее выполненное действие.

**Актор:** Пользователь.

**Предусловия:**
- В редакторе открыт документ.
- Ранее было выполнено хотя бы одно действие, которое поддерживает отмену.

**Триггер:** Пользователь нажимает кнопку «Отменить» или использует соответствующую комбинацию клавиш.

**Основной сценарий:**
1. Пользователь инициирует отмену последнего действия.
2. Приложение определяет последнее действие, доступное для отмены.
3. Приложение отменяет это действие.
4. Приложение обновляет содержимое и отображение документа.

**Альтернативные и негативные сценарии:**
- Действий для отмены нет — приложение не выполняет отмену и сообщает об отсутствии доступных действий.

**Результат:** Последнее действие отменено, документ возвращён к предыдущему состоянию.

### UC-07. Возврат отменённого изменения

**Цель:** Пользователь хочет вернуть действие, которое ранее было отменено.

**Актор:** Пользователь.

**Предусловия:**
- В редакторе открыт документ.
- Ранее было отменено действие, которое ещё доступно для возврата.

**Триггер:** Пользователь нажимает кнопку «Повторить» или использует соответствующую комбинацию клавиш.

**Основной сценарий:**
1. Пользователь инициирует возврат отменённого действия.
2. Приложение определяет последнее действие, которое можно вернуть.
3. Приложение повторно применяет это действие.
4. Приложение обновляет содержимое и отображение документа.

**Альтернативные и негативные сценарии:**
- Нет отменённых действий для возврата — приложение не выполняет действие и сообщает об этом.
- Пользователь совершил новое изменение после отмены — ранее отменённое действие становится недоступным для возврата, если это предусмотрено правилами истории действий редактора.

**Результат:** Ранее отменённое действие повторно применено.

### UC-08. Изменение масштаба текста

**Цель:** Пользователь хочет увеличить или уменьшить отображаемый размер текста для более удобной работы.

**Актор:** Пользователь.

**Предусловия:**
- Приложение запущено.
- Открыт интерфейс редактора.

**Триггер:** Пользователь выбирает функцию изменения масштаба текста.

**Основной сценарий:**
1. Пользователь нажимает кнопку увеличения или уменьшения масштаба.
2. Приложение изменяет масштаб отображения текста.
3. Приложение обновляет отображение документа с новым масштабом.

**Альтернативные и негативные сценарии:**
- Достигнут максимально допустимый масштаб — дальнейшее увеличение невозможно.
- Достигнут минимально допустимый масштаб — дальнейшее уменьшение невозможно.

**Результат:** Текст отображается с выбранным масштабом. Содержимое документа при этом не изменяется.

### UC-09. Создание и оформление блока кода

**Цель:** Пользователь хочет создать отдельный блок кода и поместить в него программный код или другой предварительно форматированный текст.

**Актор:** Пользователь.

**Предусловия:**
- В редакторе открыт документ.
- Пользователь может изменять содержимое документа.

**Триггер:** Пользователь выбирает функцию создания блока кода.

**Основной сценарий:**
1. Пользователь выбирает место в документе для создания блока кода.
2. Пользователь инициирует вставку блока кода.
3. Приложение создаёт новый блок кода с соответствующим Markdown-оформлением.
4. Пользователь вводит или вставляет содержимое блока.
5. Приложение отображает блок в соответствующем формате.

**Альтернативные и негативные сценарии:**
- Пользователь отменяет создание блока — новый блок не добавляется.
- Пользователь оставляет блок пустым — пустой блок остаётся в документе или удаляется согласно правилам редактора.

**Результат:** В документ добавлен оформленный блок кода.

### UC-10. Просмотр количества слов и символов

**Цель:** Пользователь хочет узнать количество слов и символов в документе.

**Актор:** Пользователь.

**Предусловия:**
- Приложение запущено.
- В редакторе открыт документ.

**Триггер:** Пользователь открывает информацию о статистике документа или обращает внимание на соответствующий счётчик.

**Основной сценарий:**
1. Пользователь открывает статистику документа или обращается к отображаемому счётчику.
2. Приложение анализирует текущее содержимое документа.
3. Приложение подсчитывает количество слов и символов.
4. Приложение отображает полученные значения пользователю.

**Альтернативные и негативные сценарии:**
- Документ пустой — приложение отображает нулевое количество слов и символов.
- Пользователь изменяет содержимое документа — статистика обновляется в соответствии с текущим содержимым.

**Результат:** Пользователь видит актуальное количество слов и символов в документе.
